# 验收记录与下一阶段清单

## v0.1.0 自动验证范围

- Swift 单元测试：新隧道默认关闭代理、偏好往返、错误配置拒绝、端口 / 主机 / profile ID 校验。
- Go 单元测试：保留节点与规则，覆盖 TUN、DNS 监听、LAN、控制端口及物理网卡绑定。
- Xcode：macOS 应用、Packet Tunnel App Extension、登录助手，`arm64` + `x86_64`。
- 打包：包含 Mihomo 与启动器的 universal ZIP、DMG，SHA-256。
- 网站：静态资源、section 链接、连接 / 断开、代理切换、手机布局、JavaScript 错误。

这些检查不证明 VPN 已握手，也不替代签名后运行。CI 的实际结果以对应 commit 的 Actions 为准。

## 正确签名构建中的真实联网验收

以下项目在 v0.1.0 发布时尚未完成：

- [ ] 首次 VPN 授权、钥匙串访问、App Group 访问。
- [ ] 导入 / 编辑 / 复制 / 删除 / 导出，编辑后仍保留代理设置。
- [ ] 代理关闭：原有 WireGuard 路由、DNS、IPv4、IPv6。
- [ ] 内置代理：子进程能在扩展沙箱内启动并监听。
- [ ] 外部代理：可达端口成功，端口不存在时回滚。
- [ ] 内置核心绑定实际 utun；抓包验证直连与代理节点出站路径。
- [ ] 错误 YAML、规则下载失败、端口冲突，均不误报启动成功。
- [ ] 启动中取消、快速启停、切换隧道，不残留进程。
- [ ] 核心崩溃、扩展崩溃、休眠唤醒、Wi-Fi / 以太网切换。
- [ ] 按需连接在主应用关闭后仍使用正确代理偏好。
- [ ] 断开后由系统撤销隧道代理，不覆盖其他用户网络设置。
- [ ] 大型配置与远端 provider、DNS 引导、IPv6-only 网络。

项目目前只检查代理监听 TCP 端口，不强制检查 WireGuard 握手、某个网站或代理节点是否可用。没有实现网络 kill switch；隧道断开后系统可能使用原有物理网络。请勿将回滚描述为防泄漏保证。
