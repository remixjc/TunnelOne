# TunnelOne v0.2.3 · Safety Startup Timing Fix · Signed Beta

对齐 `WireGuard与Clash安全启动.command` 的执行顺序，修复在 WireGuard 尚未向系统报告启动完成时就执行联网检查的问题。建议使用“连接时带入代理”的用户升级。

- 先检查 Clash 配置和物理网络代理，等待 `127.0.0.1:7890` 端口可连接，再启动 WireGuard。
- 底层适配器与路由就绪后，向 macOS 报告隧道建立；读取系统连接状态，匹配本次 utun 的 Connected 状态，再等待 1 秒，然后检查路由、同步隧道临时服务代理，并行验证百度直连与 Google 代理。
- 系统已连接时界面显示“正在验证连接”和实际检查阶段；两项检查通过后才显示“隧道与代理已连接”。检查失败仍自动断开本次 WireGuard，保留原有 Clash。
- 保存 curl 退出码、HTTP 状态和 stderr；启动失败弹窗与连接日志显示实际失败原因。用户主动取消时不弹出旧检查的错误，旧报告仍可读取。
- 版本 **0.2.3（build 7）**。保留 v0.2.2 的 WebKit 沙盒权限及原生加载错误提示。

下载 `TunnelOne-0.2.3-macOS-universal-signed.dmg` 或 `-signed.zip`。退出旧应用，将新版放入 `/Applications`，打开后按 macOS 提示允许更新网络扩展。支持 macOS 13+、Apple Silicon 和 Intel。

自动化覆盖 Connected 等待、超时、稳定期断开 / 取消、代理写入归属、双目标探测、错误详情、报告兼容及界面状态。真实新扩展下的联网与失败回滚仍需安装后验收；本次不自动中断当前正在使用的连接，保持 Beta。
