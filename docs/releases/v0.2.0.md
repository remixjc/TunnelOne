# TunnelOne v0.2.0 · System Extension Beta

TunnelOne now packages its WireGuard provider as a macOS System Extension for Developer ID distribution. Install the signed app in `/Applications`, allow the network extension when macOS asks, and then import and connect your tunnel.

- Adds system-extension activation, version replacement and removal from the app menu.
- Moves system-side configuration to immutable, root-owned snapshots. The GUI retains its user-keychain copy; signed XPC messages transfer configurations without putting private keys or YAML credentials into VPN preferences.
- Isolates snapshots by the XPC caller's UID and runs Mihomo as that ordinary user, with a root supervisor responsible only for process lifetime.
- Adds universal bundle checks, snapshot isolation tests, Developer ID profile validation, Apple notarization, app/DMG stapling and signed release packaging.
- Requires macOS 13 or later for per-message XPC code-signing requirements.

`-signed.dmg` / `-signed.zip` are uploaded only after Developer ID checks and Apple notarization succeed. `-preview` files are unsigned development artifacts and cannot activate the VPN provider.

This release remains a **Beta**. Signing and notarization verify distribution requirements; they do not prove the WireGuard handshake, remote proxy availability, wake recovery or multi-user behavior. Device acceptance status is recorded in `docs/acceptance.md`.

Back up/export existing tunnels before switching from a preview or another WireGuard client. Stop the other WireGuard tunnel before testing TunnelOne. To uninstall, export and remove TunnelOne tunnels first, then use the app's “移除网络扩展…” menu item before deleting the app.
