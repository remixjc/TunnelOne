# TunnelOne v0.2.4 · Through-Tunnel Connectivity Probe · Signed Beta

修正外部 Clash 安全启动的国内直连检查。v0.2.3 已修正 Connected 时序，但在 Packet Tunnel Provider 内启动的普通 curl 仍使用扩展的网络上下文，不能等同于终端中的普通客户端。实机出现扩展内 `curl 6 / Could not resolve host` 后回滚，而同一隧道连接期间终端百度访问返回 200 的情况。

- 国内直连改用 `NEPacketTunnelProvider.createTCPConnectionThroughTunnel`，明确通过本次 WireGuard 隧道解析域名、建立 TCP/TLS 并检查百度 HTTP 响应。实机验收发现该 API 仍会采用系统 HTTP 代理；这会与隧道接口要求冲突并导致超时，v0.2.5 修正 macOS 15+ 的路径。使用默认系统证书验证，不硬编码百度 IP、不修改 DNS 配置，也不把预解析或其它网站的成功当成本次成功。
- 保留“Clash 端口 → WireGuard → 系统 Connected → 稳定 1 秒 → 路由 / 代理核验 → 双目标检查”的顺序。
- 国外检查继续显式使用 `127.0.0.1:7890` 访问 Google，保留 HTTP、curl 退出码和错误详情。
- 原生直连检查覆盖 4 秒建连 / 7 秒总超时、取消、TLS 及读写错误、响应头长度限制、分片与临时 HTTP 响应。响应头中的 HTTP 200–399 才算成功；不跟随重定向、不关闭证书验证。日志记录每项探测所用路径。
- 版本 **0.2.4（build 8）**。支持 macOS 13+、Apple Silicon 和 Intel，继续保留沙盒 WebKit 修复。

安装前断开隧道并退出旧应用，将 signed 安装包内的 TunnelOne 放入 `/Applications`，按系统提示更新网络扩展。本版继续保持 Beta。
